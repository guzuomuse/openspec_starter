# Verification lens（透镜 B 的判定标准）

问题只有一个：**改动带来的回归，有没有一条会变红的断言钉住它？**

## 证据规则

- 说一条测试覆盖或漏掉什么之前，先打开它读。
- 说"没有测试"之前，先按符号名和 import 搜全仓库。按预期路径猜不算。
- 说清你搜了什么、看到哪一步。撑不住的结论直接丢掉。
- 不要给严重度、置信度、优先级——那是 triage 的事。

## 六步

### 1. 筛

逐个改动面看，跳过不改变行为的：格式化、注释、重命名、纯类型改动、
原样透传的 getter。跳过之后就别再看它的调用方和测试。

也跳过不值得测的：静态文本（prompt、文档）、LLM 输出、
构建/依赖/配置这类由 CI 自己验证的。

**不要跳过测试本身的改动**：被删掉或弱化的测试，在第 4、5 步查。

全被跳过就报干净。

### 2. 命名改动后的行为

对每个留下的改动面，说清和之前哪里不同：输出、副作用、分支、错误路径、
schema 或事件形状、默认值、校验规则、对外契约。一个行为一条。

### 3. 找到观察者

把每个改动过的行为追到真正观察它的代码：直接调用方、注册入口（路由、命令、DI）、
契约消费方（schema、事件、API、读库的地方）。

1~3 跳通常够。遇到"测试能接住""消费方看不到这个变化""下一跳只能猜"就停。

### 4. 说出回归，然后查测试

**先问一句：spec 承诺过这个行为吗？** 回到 `specs/`（必要时 `design.md`）确认：

- 承诺过 → 往下走，缺断言就是 gap。
- 没承诺过（spec 未定义的输入域、没写的错误分类、实现内部细节）→ **不是 gap**。
  记成 `contract-gap`：这处行为没有契约，交 triage 按 `decision_needed` 处理
  （"要钉住它得先写 requirement"）。给未定义域补断言，等于用测试把某个实现选择
  冻结成契约——这正是 spec 轴和 verification 轴给出相反处方的唯一来源。

一句话：**回归是"承诺过的行为"被破坏，不是"代码里的行为"被破坏。**

对每个消费方，说出它能看到的最小真实回归：分支反了、默认值丢了、字段漏了、
旧错误码回来了、集成调用被跳过。

> "这行删掉也没有测试会红"不是回归。

没有回归（状态不可达、防御性分支、别处已经保证了）→ 丢掉这条路径，不算 finding。

然后读相关测试，问：**这个回归会让某条断言失败吗？**

- 会 → 已验证，无 finding。
- 没有测试跑这条路径，或测试被跳过、不稳定、平时不跑，或跑了但没检查改动结果
  → `regression gap` / `broken-verification gap`。

一条测试算数，必须满足：平时会跑 + 有断言观察改动的输出、分支或契约。

**不算数的情况**：对源码文本断言、只断言不抛错、只有快照、
检查 mock 调用次数或日志、手动检查、把集成 mock 掉的测试、
端到端跑过但没检查改动结果的测试、陈旧的断言或 fixture。

### 5. 查被碰过的测试

测试断言的内容不是这次改动后应有的行为 → `stale-verification gap`，
说明它应该断言什么。测试已经不再验证任何东西 → 建议删掉。

### 6. 确认

写 finding 之前，把依赖的测试和搜索结果重新打开一遍。确认：
回归真实存在，且你读过的测试确实接不住它。

## 变异测试：钉住"是哪一行让它变绿"

`tasks.md` 里的自证证明的是"**整段**实现是载荷"，不证明"每一行是载荷"。要找"删掉它也没有断言会红"的行，
用仓库自带的 `scripts/mutate-check.mjs`（模板的 `scripts/` 随 `install.ps1` 分发）：

```bash
node scripts/mutate-check.mjs path/to/mutations.mjs
node scripts/mutate-check.mjs path/to/mutations.mjs --cmd "node --test test/x.test.mjs"
```

清单是一个 ESM 文件，导出数组；`apply` 返回改坏后的源码：

```js
export default [
  { id: "M1", file: "src/roman.mjs", note: "表改成升序", apply: (s) => s.replace(/…/, "…") },
];
```

判读：

- `KILLED` = 有断言杀掉它，好；
- `SURVIVED` = 改坏了却全绿 → 那行/那个分支没有区分力，记一条 `low`/`verification`；
  若能证明它完全冗余（删了行为不变），直接删；
- `NOOP` = 变异没改到字符（正则没匹配），是用法错误，不能算 KILLED；
- **等价变异**（改写法不改行为，如 `out += x` → `out = out + x`）存活是正常的，从清单里删掉，
  别为它补断言——那样只会写成同义反复。

脚本在临时副本里跑，不动工作区；任何 `SURVIVED`/`NOOP` 都让退出码非 0。
`tasks.md` 里的自证不能替代这一步：自证看"整段"，变异看"逐行"。

## 不要报

- 编译器或类型检查器保证的
- 集成/契约/端到端测试已经验证过的
- 单纯的覆盖率低、没有测试文件
- 本次没碰的代码
- spec 未承诺过的行为 → 记 `contract-gap`（要契约先写 requirement），不记 gap

追踪过程中顺手发现的缺陷，另起一节 `其他发现`，不要专门去找。

## 输出格式

每个 gap 一个块，必须能独立站住（triage 不会再验一遍 gap）：

```markdown
### <一行标题，点出缺的是什么验证>

- **改动的面**：<行为或契约>，`file:line`
- **受影响的消费方**：具体到名字和 `file:line`，不要写"该函数的调用方"
- **现有测试证据**：相关测试断言了什么 `file:line`；或你搜了什么、结果如何
- **缺的验证**：应该补的断言，或旧断言应该改成什么
- **演示**：回归是什么，以及你读的测试为什么不会红
- **后果**：什么会带着问题上线
- **处置**：要加或要改的测试，贴合本仓库已有的测试写法
```
